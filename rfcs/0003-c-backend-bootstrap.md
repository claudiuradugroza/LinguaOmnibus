## 1. Summary

This RFC proposes a C-transpiler backend for the Lingua Omnibus compiler (`loc`), to be used as the **Phase 1 (MVP) backend**. Instead of targeting LLVM IR directly, `loc` transpiles LIR to portable C99 code, which is then compiled by `gcc`/`clang`/`tcc` to native machine code.

The C backend is a **bootstrap backend** — it exists to validate the LIR and the entire compilation pipeline before investing in a native LLVM or custom assembly backend.

## 2. Motivation

### 2.1 Why C, not LLVM, for Phase 1

1. **Validates LIR independently**: If LIR → C produces correct programs, the LIR is correct. With LLVM, bugs in LIR and bugs in codegen are indistinguishable.
2. **Bootstrappable (Principle 4)**: TCC + C-transpiler = complete bootstrap in ~3MB. LLVM cannot be bootstrapped without LLVM.
3. **Reproducible (Principle 3)**: `gcc -O2 -ffile-prefix-map=... -fno-ident` produces deterministic binaries. Tested for 20+ years.
4. **Zero installation friction**: gcc is pre-installed on every Unix system. No 500MB LLVM download.
5. **Time to first binary**: 2 weeks instead of 2 months.

### 2.2 When to transition to LLVM

After the C backend produces correct binaries for all 107 conformance tests, Fibonacci, and pons hello-world. Then LLVM provides codegen quality, not correctness.

## 3. Architecture

```
impl/loc/src/backend/
├── mod.rs           # Backend trait, BackendError, select_backend
├── c.rs             # LIR → C transpiler (Phase 1)
├── llvm.rs          # LIR → LLVM IR (Phase 2, future)
└── x86_64.rs        # LIR → asm (Phase 3, future)
```

### 3.1 Backend trait

```rust
pub trait Backend {
    fn name(&self) -> &'static str;
    fn emit(&self, module: &LirModule) -> Result<Vec<u8>, BackendError>;
}
```

### 3.2 C backend approach

- Emit C99 source to a temporary file
- Invoke `cc -O2 -std=c99 -o <output> <temp.c>`
- Read the output binary
- Return it

### 3.3 MVP LIR instruction subset

| LIR instruction | C equivalent |
|---|---|
| const.int N | int64_t N |
| const.float F | double F |
| const.str "S" | "S" |
| const.bool true/false | 1 / 0 |
| const.unit | (void) |
| add a, b | (a + b) |
| sub a, b | (a - b) |
| mul a, b | (a * b) |
| div a, b | (a / b) |
| mod a, b | (a % b) |
| eq a, b | (a == b) |
| ne a, b | (a != b) |
| lt a, b | (a < b) |
| le a, b | (a <= b) |
| gt a, b | (a > b) |
| ge a, b | (a >= b) |
| call @f(a, b, c) | f(a, b, c) |
| ret v | return v; |
| ret unit | return; |
| br L | goto L; |
| condbr c, T, F | if (c) goto T; else goto F; |
| label L: | L: |

## 4. Generated C conventions

- Single file output (no multi-file for MVP)
- All function names prefixed with `lo_`
- All local variables sanitized (alphanumeric + underscore)
- Header: `// Generated by loc 0.1.0 — do not edit`
- Only C99 features TCC supports
- No absolute paths (reproducibility)
- No timestamps or random (reproducibility)
- Link only against libc

## 5. Integration with loc CLI

```
loc build <file>.lo --backend=c --target=x86_64
loc run <file>.lo
```

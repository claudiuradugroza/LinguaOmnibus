01 · The Problem

700 million excluded by one barrier.

Every modern programming language is, in essence, a dialect of English. if, else, function, return — 40+ keywords, one language.

Non-English speakers must learn two languages to write one program. This is not a technical limit. It is a historical accident that has been accepted for 70 years because nobody rebuilt the foundation.

The insight: Semantics ≠ Syntax. The meaning of add(a, b) is universal; the word add is not. Separate them, and any human language becomes a valid surface.
📊

By the numbers

~700M potential programmers excluded by the English barrier.
~7,000 living human languages.
0 mainstream programming languages with native multilingual syntax.

02 · The 13 Constitutional Principles

Every technical decision must pass all 13.

These principles are regression tests for the vision. If a design choice violates any of them, it is rejected — even if it is faster to implement. They are the reason Lingua Omnibus can be trusted by anyone.

03 · Architecture

Three layers. One semantics.

Languages touch only Layer 1. Layers 2 and 3 never see natural language — they see only the unified AST and the LIR. That is why adding a language never requires changing the compiler.

Layer 1 · Multilingual Frontend
Per-pack parsers → unified AST
EN · English RO · Română FR · Français DE · Deutsch ES · Español JA · 日本語 + any pack

Each pack is pure data (JSON + tests). Adding a language MUST NOT require changing the compiler (CONV-061).

↓
Layer 2 · LIR (Universal Semantic Core)
Lingua Intermediate Representation
Type inference Constant folding DCE Inlining Formal verification

Language- and architecture-agnostic. Independent SemVer (CONV-031). Byte-identical output across packs (CONV-042).

↓
Layer 3 · Multi-Target Backend
Native code for every target
x86_64 ARM64 RISC-V PowerPC WASM QPU · OpenQASM 3.0
04 · The Unified AST Promise

Same program. Three languages. One AST.

This is not marketing. It is GRAM-053, a normative rule from SPEC-02, verified on every commit by conformance/gram/050/fib-en-ro.lo. Two files that differ only in #lingua: MUST produce byte-identical canonical ASTs.

fib.lo · 3 packs · 1 semantic output loc dump-ast --canonical
🇬🇧 English · EN
#lingua: EN
function fib(n: Integer) returns Integer:
    if n <= 1 then:
        return n
    else:
        return fib(n-1) + fib(n-2)
🇷🇴 Română · RO
#lingua: RO
funcție fib(n: Întreg) returnează Întreg:
    dacă n ≤ 1 atunci:
        returnează n
    altfel:
        returnează fib(n-1) + fib(n-2)
🇯🇵 日本語 · JA
#lingua: JA
関数 fib(n: 整数) 返す 整数:
    もし n ≤ 1 ならば:
        返す n
    そうでなければ:
        返す fib(n-1) + fib(n-2)
▶ canonical AST (identical for all three, byte-for-byte)
{"kind":"FnDecl","name":"fib","params":[{"kind":"Param","name":"n","type":"int"}],
 "ret":"int","body":{"kind":"Block","body":[{"kind":"IfStmt",
   "cond":{"kind":"BinaryOp","op":"<=",...},"then":{...},"else":{...}}]}}
Verified on every commit: diff <(loc dump-ast en.lo --canonical) <(loc dump-ast ro.lo --canonical) returns empty. Binaries compiled from each are byte-identical (CONV-042).
05 · Language Pack = Pure Data

Adding a language = adding a JSON file.

This is CONV-061: adding a new natural language MUST NOT require changing the compiler. If it does, that is a spec bug — filed as an RFC. The language pack is the contract.

Romanian pack (excerpt)

// langpacks/ro/keywords.json
{
  "iso": "ro",
  "name": "Română",
  "version": "2026-01-01",
  "script": "Latin",
  "direction": "ltr",
  "keywords": {
    "KW_FUNCTION": ["funcție", "functie"],
    "KW_RETURN":   ["returnează", "returneaza"],
    "KW_IF":       ["dacă", "daca"],
    "KW_THEN":     ["atunci"],
    "KW_ELSE":     ["altfel"]
  }
}

Why this matters

  • Anyone can contribute a language — no compiler knowledge required, only native fluency.
  • Diacritics and ASCII forms coexist — funcție and functie both map to KW_FUNCTION.
  • 40 universal keyword slots (CONV-063) — same semantics, different words.
  • Packs are versioned by ISO 8601 date (CONV-032) — no SemVer ambiguity for natural-language changes.
  • Federated registry (CONV-080) — anyone can host a pack registry; there is no mandatory "official" one.
Invitation: If you speak a language not yet in langpacks/, you are one JSON file away from making Lingua Omnibus accessible to your community.

08 · Risk Mitigation

Why anyone can trust this project.

Risk Mitigation
Vendor capture Apache 2.0 + foundation governance + explicit fork rights (Principles 9, 10)
Registry abuse Federated registries; no mandatory "official" one (CONV-080, Principle 5)
Telemetry creep Zero telemetry by default; opt-in only and audited (Principle 7)
Format lock-in All formats (.lo, LIR, .ldb, lopm manifest) documented publicly (Principle 8)
Project abandonment LTS + lo-migrate + bootstrappable toolchain (Principles 4, 13)
